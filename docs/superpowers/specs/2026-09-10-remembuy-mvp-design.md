# REMEMBUY MVP — 설계 문서

날짜: 2026-09-10
원본 스펙: `REMEMBUY_스펙_안티그래비티용.md`

## 1. 범위

- 1단계 MVP만 구현: **localStorage 기반 로컬 전용** 웹 앱
- 공유 피드 / 가족 케어는 실제 서버 연동 없이, 고정 더미 데이터 + 로컬 저장까지만 동작
- 디자인 기준이 되는 별도 HTML 프로토타입은 없음 — 원본 스펙 6번(디자인 가이드)을 기준으로 새로 디자인

## 2. 아키텍처

- **Vite + React + TypeScript + Tailwind CSS**, 순수 SPA (백엔드 없음)
- 개발 서버 포트 고정: `http://localhost:7777` (`vite.config.ts`의 `server.port: 7777`)
- 라우팅: `react-router-dom`, 8개 라우트 (홈 / 상품상세 / 랭킹 / 알림 / 공유피드 / 가족케어 / 새로기록 / 컬렉션)
- 상태 관리: 별도 라이브러리 없이 React Context + `useReducer`로 "보관함(Locker)" 전역 상태 하나만 관리
- 영속성: 커스텀 훅 `useLocalStorage`로 Context 상태를 `localStorage`에 자동 동기화. 저장된 데이터가 없으면 시드 데이터를 주입
- 공유 피드 / 가족 케어 데이터는 사용자 보관함과 분리된 별도 더미 데이터셋(고정 JSON)으로 표시. 공유 피드의 "저장하기"는 해당 항목을 복사해 내 로컬 보관함에 추가

## 3. 데이터 모델

```ts
type Location = { id: string; name: string; colorToken: string }
type Category = { id: string; locationId: string; name: string }
type Item = {
  id: string
  name: string
  locationId: string
  categoryId: string
  note?: string
  rating?: number          // rating과 daysUntilEmpty는 상호 배타적
  daysUntilEmpty?: number
  place?: string           // 구매처
  restockCycle?: string | null
  affiliateUrl?: string | null
  createdAt: string
}
```

- `Location`/`Category`는 별도 엔티티로 관리하고 `Item`은 id로 참조 (이름 변경 시 items 전체를 건드리지 않기 위함)
- `restockCycle`이 의미 없는 카테고리(상의·하의·아우터, 침구, 구급용품 등)는 `null` 허용
- `rating` vs `daysUntilEmpty`는 등록 폼에서 토글로 택1

## 3-1. 컬렉션 / 완성도 (게임화)

**핵심 개념**: 각 카테고리마다 "표준 품목 마스터 리스트"를 갖고, 내가 기록한 상품이 그중 몇 개를 커버하는지로 완성도(%)를 계산 — 도감을 채워나가는 재미 + "지금 없는 것"을 알려주는 용도.

```ts
type MasterItem = { id: string; name: string }
// Category에 추가
type Category = {
  id: string
  locationId: string
  name: string
  masterItems: MasterItem[]
}
// Item에 추가
type Item = {
  // ...기존 필드
  masterItemId?: string  // 새로 기록하기에서 표준 품목과 매칭 시 연결, 커스텀 상품이면 없음
}
```

- 새로 기록하기에서 카테고리를 고르면 해당 카테고리의 표준 품목을 추천 칩/드롭다운으로 보여주고 선택 시 연결. 목록에 없으면 직접 입력(커스텀 상품, 완성도 계산에는 포함되지 않음)
- **카테고리 완성도** = 보유한 고유 `masterItemId` 수 / 해당 카테고리 `masterItems` 총 개수
- **장소 완성도** = 소속 카테고리 완성도의 평균 — 홈/컬렉션 화면에서 장소 아이콘 둘레의 원형 게이지(도넛형 프로그레스 링, SVG `stroke-dasharray`)로 시각화, 장소 고유 색상을 게이지 색으로 사용
- 카테고리는 "상용화"된 세분화 기준으로 마스터 리스트 구성 (예: 스킨케어 → 클렌징폼/스킨·로션/에센스/크림/선크림처럼 실제 마트·올리브영 진열 단위)

## 4. 화면 구성 (8개)

1. **홈(보관함)** `/` — 검색창, 장소별 원형 아이콘 내비게이션(10개+전체), "전체·임박만" 필터 탭, 카테고리별 상품 카드 목록. 클릭 시 상세 이동
2. **상품 상세** `/item/:id` — 썸네일, 이름, 장소>카테고리 경로, 별점/D-day, 메모, 구매처, 재구매 주기, "다시 담기"(placeholder), "메모 수정하기"
3. **랭킹** `/ranking` — 카테고리 칩 선택 → 별점 내림차순 순위, 1위 "다시 살래요" 뱃지
4. **알림** `/notifications` — `daysUntilEmpty` 임박(7일 이하) 상품 목록, 예상 소진일, "다시 담기"
5. **공유 피드** `/feed` — 고정 더미 데이터 카드, "저장하기" → 내 로컬 보관함에 복사 추가
6. **가족 케어** `/family` — 더미 가족 계정 보관함 요약, "가족 초대하기"는 토스트만 표시
7. **새로 기록하기** `/new` — 이름, 장소→카테고리 연동 선택, 구매처, 재구매 주기, 별점/D-day 택1, 메모, (선택) 카테고리의 표준 품목 중 매칭되는 항목 선택. 저장 시 홈 이동
8. **컬렉션** `/collection` — 상단에 10개 장소 아이콘, 각 아이콘 테두리에 완성도(%)만큼 채워지는 원형 게이지(도넛형 프로그레스 링, 장소 고유 색상 사용) + `%` 텍스트. 장소 클릭 시 해당 장소의 카테고리별 진행률(바)과, 각 카테고리를 펼치면 보유 품목(체크)/미보유 품목(빈칸+"기록하기" 바로가기)을 도감처럼 표시

공통 레이아웃: 하단 탭바(홈/랭킹/알림/공유/가족/컬렉션) + 홈 화면에 "새로 기록하기" 진입 버튼(플로팅 또는 상단). 홈 화면의 장소별 원형 아이콘 내비게이션에도 동일한 게이지 스타일을 적용해 일관성 유지.

## 6. 검증 계획

`npm run dev`로 `http://localhost:7777` 구동 후 브라우저에서 8개 화면 전부 클릭 테스트:
- 시드 데이터 로딩 확인
- 홈 검색/필터/장소 내비게이션 및 원형 게이지 표시
- 랭킹 카테고리별 정렬
- 알림 임박 판정 로직
- 공유 피드 "저장하기" → 홈 보관함 반영
- 새로 기록하기 → 저장 → 홈/랭킹/알림 반영까지 골든 패스
- 새로 기록하기에서 표준 품목 매칭 → 컬렉션 화면의 완성도(%)와 게이지가 즉시 갱신되는지 확인
- 컬렉션 화면에서 장소별 게이지 클릭 → 카테고리 진행률·보유/미보유 품목 목록 정상 표시
