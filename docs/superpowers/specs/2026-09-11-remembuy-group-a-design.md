# REMEMBUY Phase 2 — Group A (UI/UX 개선) 설계 문서

날짜: 2026-09-11
선행 문서: `2026-09-10-remembuy-mvp-design.md` (완료·병합됨), `2026-09-10-remembuy-mvp.md` (구현 계획, 완료됨)

## 1. 범위

MVP(로컬 전용 localStorage 앱)의 기존 화면 구조를 아래와 같이 개선한다. **백엔드·AI·다중 사용자 기능은 이번 범위에 포함하지 않는다** — 그런 요구사항은 별도로 그룹 B(서버 기반 기능: 가족/구매처/구독)와 그룹 C(AI 자동화 파이프라인: 사진·링크 등록, 카테고리 자동 확장)로 분리해서 각각 별도 스펙으로 진행한다.

- 공유 피드·가족 케어 화면은 이번 그룹 A에서 변경하지 않는다(그룹 B에서 다룸).
- 컬렉션 화면은 현재 수준(카테고리별 보유/미보유 도감형 체크리스트, 장소별 게이지)이 이미 충분하다고 확인되어 변경하지 않는다.
- 오픈소스 후보 검토: `Ponytail`(AI 에이전트 코딩 규율 도구), `Graphify`(코드베이스 지식 그래프 분석 도구)는 REMEMBUY 앱의 런타임 의존성과 무관하여 채택하지 않는다. `OmniRoute`(다중 AI 모델 게이트웨이)는 앱 코드가 아니라 향후 그룹 C의 AI 자동분류 파이프라인을 설계할 때 AI 게이트웨이 후보로 검토한다 — 이번 그룹 A 구현에는 포함되지 않는다.

## 2. 데이터 모델 변경

```ts
type Item = {
  id: string
  name: string
  locationId: string
  categoryId: string
  masterItemId?: string
  note?: string
  recommendation?: 'recommend' | 'notRecommend'  // 기존 rating(1~5)을 대체
  daysUntilEmpty?: number                         // 유지. recommendation과 상호배타
  price?: number                                  // 신규 — 사용자가 직접 입력
  place?: string
  restockCycle?: string | null
  affiliateUrl?: string | null                    // 유지 — "구매하기" 버튼에 연결
  createdAt: string
}
```

- `recommendation`과 `daysUntilEmpty`는 기존 `rating`/`daysUntilEmpty` 관계와 동일하게 상호 배타적으로 사용한다(등록 폼에서 토글로 택1).
- **기존 시드 데이터 마이그레이션 규칙**: `rating >= 4` → `recommendation: 'recommend'`, `rating <= 3` → `recommendation: 'notRecommend'`. `rating`이 없던 항목(`daysUntilEmpty` 기반 항목)은 그대로 `daysUntilEmpty`만 유지한다.
- `RatingStars` 컴포넌트와 `rating` 필드를 사용하는 모든 코드(선택 로직, 랭킹 정렬, 폼)는 `recommendation` 기반으로 교체된다. `getRankingForCategory` 셀렉터는 "정렬 기준: `recommendation === 'recommend'`인 항목 우선, 그 다음 `notRecommend`, 마지막으로 미평가"로 재정의된다.

### 알림 읽음 상태 (신규, 별도 로컬 상태)

```ts
// localStorage key: "remembuy:seenNotificationIds"
type SeenNotificationIds = string[]  // Item id 목록
```

- `LockerContext`와는 독립적인 별도의 `useLocalStorage<string[]>('remembuy:seenNotificationIds', [])` 상태로 관리한다(알림 읽음 여부는 상품 데이터 자체와 무관한 UI 상태이므로 분리).
- 알림 화면(`/notifications`)에 진입해 임박 상품 목록이 렌더링되는 시점에, 현재 표시된 모든 임박 상품의 `id`를 이 목록에 추가한다.
- "안읽음 개수" = 현재 임박 상품(`getUpcomingNotifications` 결과) 중 `seenNotificationIds`에 없는 것의 개수. 1개 이상이면 벨 아이콘에 빨간 점을 표시한다(정확한 개수까지는 표시하지 않고 점 하나로 충분— 요구사항이 "빨간색 동그라미로 읽지않은 알림 표기"이므로).

## 3. 네비게이션 구조 변경

- 하단 탭바: 6개(홈/랭킹/알림/공유/가족/컬렉션) → **5개**(홈/랭킹/공유/가족/컬렉션). 알림 탭 제거.
- `AppLayout`에 공통 상단 헤더를 추가하고, 우측에 고정된 벨 아이콘 버튼을 배치한다. 클릭 시 `/notifications`로 이동. 안읽은 알림이 있으면 아이콘 우측 상단에 빨간 점(`•`, 작은 원형 배지) 표시.
- 라우트 구성 자체(`/notifications` 포함 8개 경로)는 변경 없음 — 진입 지점만 하단 탭에서 상단 아이콘으로 바뀐다.

## 4. 화면별 변경사항

### 4.1 홈 (`/`)

기존: 검색창 + 장소 아이콘 목록 + 필터 탭 + 카테고리별로 묶인 전체 상품 목록이 한 화면에 표시.

변경 후: **장소 선택 → 카테고리 타일(도감형) → 상품 목록**의 3단계 드릴다운 구조로 전환.

1. **1단계 (기본 화면)**: 검색창 + 장소 아이콘 그리드. 장소 아이콘은 장소별 전용 이모지로 교체(예: 욕실🛁, 주방🍳, 세탁실/다용도실🧺, 옷장/드레스룸👕, 화장대💄, 침실🛏️, 거실🛋️, 현관/신발장👞, 상비약함💊, 차량🚗). 각 아이콘에는 기존과 동일하게 장소 완성도 게이지가 둘러싼다. "전체" 항목은 제거한다.
2. **2단계 (장소 선택 시)**: 선택한 장소에 속한 카테고리들을 타일(그리드) 형태로 나열 — 카테고리명, 보유 상품 개수, (선택) 컬렉션 완성도 미니 배지를 표시. 이 타일 목록은 컬렉션 화면의 도감형 UI와 톤을 맞추되, 여기서는 완성도 체크리스트가 아니라 "카테고리 진입 버튼" 역할만 한다.
3. **3단계 (카테고리 선택 시)**: 해당 카테고리 안의 내 상품을 카드 목록으로 나열. 이 화면에 필터 탭 3개(전체 / 임박만 / 추천한 상품만)를 배치. "임박만"은 `daysUntilEmpty` 존재 및 임박 기준, "추천한 상품만"은 `recommendation === 'recommend'` 기준.
4. **검색**: 1단계 화면의 검색창에 입력하면 드릴다운 상태와 무관하게 전체 보관함 상품을 대상으로 검색한 결과를 평면 목록으로 즉시 보여준다(장소/카테고리 필터링 없이).
5. 상품 카드 클릭 시 상세 페이지 이동, 플로팅 "새로 기록하기" 버튼은 유지.

### 4.2 상품 상세 (`/item/:id`)

- 평점 표시를 별점 대신 **추천해요 / 비추천해요** 버튼 두 개(현재 상태 강조 표시, 클릭 시 `updateItem`으로 `recommendation` 갱신)로 교체. `daysUntilEmpty` 기반 상품은 기존처럼 D-day 표시.
- `price`가 있으면 상품명 아래 가격 표시.
- 액션 버튼: 기존 "다시 담기"(모호한 재구매 링크)를 제거하고 **"구매하기"** 버튼으로 교체 — `affiliateUrl`이 있으면 그 링크로, 없으면 비활성화 상태로 안내 문구 표시. "메모 수정하기" 버튼은 유지.
- 하단에 **"이런 상품은 어때요?"** 섹션 추가 — 현재 상품과 같은 `categoryId`를 가진 보관함 내 다른 상품을 최대 4개까지 카드로 나열(자기 자신 제외). 클릭 시 해당 상품 상세로 이동.

### 4.3 새로 기록하기 (`/new`)

- 별점 입력(1~5 숫자 입력)을 **추천해요 / 비추천해요** 토글 버튼 두 개로 교체(택1, `progressMode`가 `recommendation`일 때).
- `price`(가격) 숫자 입력 필드 신규 추가(선택 입력).
- `affiliateUrl`(구매 링크) 텍스트 입력 필드 신규 추가(선택 입력) — 지금까지는 데이터 모델에만 있고 입력 UI가 없었음.
- 장소/카테고리 선택, 표준 품목 연결, 구매처, 재구매 주기, 메모 등 나머지는 기존과 동일.

### 4.4 랭킹 (`/ranking`)

기존: 카테고리 칩을 직접 선택해서 그 카테고리의 랭킹을 봄.

변경 후: **장소 → 카테고리 → 상품 랭킹**의 3단계 드릴다운으로 전면 교체(카테고리 칩 UI 제거).

1. **1단계**: 장소 목록을 **저장된 상품 수가 많은 순으로 정렬**해서 나열(장소별 아이콘 + 상품 개수 표시).
2. **2단계 (장소 선택 시)**: 해당 장소의 카테고리 목록을 **등록된 상품 수가 많은 순으로 정렬**해서 나열.
3. **3단계 (카테고리 선택 시)**: 해당 카테고리의 상품 랭킹 — `recommendation === 'recommend'` 상품 우선, 그다음 `notRecommend`, 마지막 미평가 순으로 정렬. 1위 항목에는 기존 "다시 살래요" 배지를 유지.

`getRankingForCategory` 셀렉터의 정렬 기준을 `rating` 내림차순에서 `recommendation` 기준 정렬로 변경한다(위 3.의 정렬 규칙과 동일).

### 4.5 알림 (`/notifications`)

- 화면 내용 자체(임박 상품 목록, D-day, "다시 담기"→ 이제 "구매하기"로 문구 통일)는 유지하되, 진입 경로가 하단 탭 대신 상단 벨 아이콘으로 바뀐다.
- 화면 진입 시 위 2절의 "읽음 처리" 로직이 실행되어 `seenNotificationIds`가 갱신된다.

### 4.6 컬렉션(`/collection`), 공유 피드(`/feed`), 가족 케어(`/family`)

변경 없음 (그룹 B/C 범위 또는 현재 수준 유지로 확정됨).

## 5. 검증 계획

- 기존 34개 자동화 테스트 중 `rating` 관련 단언은 `recommendation`으로 갱신, 나머지는 유지.
- 신규/변경 테스트: `recommendation` 기반 랭킹 정렬 셀렉터, 알림 읽음 상태 훅, 홈/랭킹 드릴다운 상태 전환 로직.
- 브라우저 골든 패스: 홈에서 장소→카테고리→상품 3단계 진입, 필터 3종 동작, 상품 상세에서 추천/비추천 토글 및 즉시 반영, 가격·구매하기 버튼, 하단 추천 상품 섹션, 새로 기록하기에서 가격/구매링크 입력 후 저장, 랭킹 3단계 드릴다운(정렬 기준 확인), 상단 벨 아이콘 안읽음 표시 및 알림 화면 방문 후 사라짐.
